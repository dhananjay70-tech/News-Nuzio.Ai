CURRENT NEWS PULSE ARTICLE CARD:

Each article currently has a "Read article ↗" action.

Change the action area to:

[ 🔊 Listen ]    [ Read article ↗ ]

The "Read article" button must continue opening the original article URL exactly as it does now.

LISTEN FLOW:

When the user clicks "Listen":

1. Get the selected article's:

   * title
   * description/content
   * source
   * article ID if available

2. Create suitable narration text from the available article data.
   Prefer:

   * headline
   * description/summary
   * cleaned article content if available

3. Use the existing Nuzio TTS/audio-generation implementation if one exists.

4. If audio already exists/can be reused for the same article, reuse it instead of generating it again.

5. While generating/loading audio:
   Show:
   "Preparing audio..."

6. When audio is ready:
   Start playback through the EXISTING Nuzio bottom audio player.

7. The existing bottom player should display the selected article title and support the existing playback controls.

8. The Listen button should visually indicate the current state:

   Idle:
   🔊 Listen

   Loading:
   ⏳ Preparing...

   Playing:
   🔊 Playing

   Error:
   ⚠️ Try again

9. If the user clicks Listen on another article:
   Stop/switch the current article and play the newly selected article.

10. If TTS/audio generation fails:

    * Do not crash the News Pulse page.
    * Show a small user-friendly error.
    * Keep "Read article" working.
    * Allow the user to retry.

IMPORTANT UX:

Do NOT automatically play audio when:

* News Pulse page loads
* timeline loads
* ingestion completes
* cluster is opened

Audio must only start after the user explicitly clicks Listen.
